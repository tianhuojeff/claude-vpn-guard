# 测试报告（v1.0.0，2026-11-01）

环境：Windows 11 Education 10.0.26200，.NET Framework 4.8.09221，Clash Verge（Mihomo v1.19.32，全局模式 + 系统代理，TUN 关），Claude 桌面版 MSIX 4.4212.0.0。

> 说明：开发过程在**非管理员**会话中进行，并且这台机器上正运行着 Claude 桌面版本身（开发它的会话就在其中）。因此**没有在本机安装服务、也没有创建任何防火墙规则**。所有需要管理员 / 会改系统防火墙的测试都标为「未验证」，并提供了一键实测命令 `selftest` 供你在管理员终端执行。

## 1. 已实际执行并通过

### 1.1 编译
`scripts\build.ps1`：三个 EXE（服务、GUI、测试）均用系统自带 csc（C# 5 / .NET Framework 4.8）编译成功，无警告错误。

### 1.2 单元测试 —— 52 / 52 通过
原始输出：`evidence-unit-tests.txt`（原始输出未随公开版发布）。覆盖：
- 地址计算：IPv4 补集精确等于 `0.0.0.0-126.255.255.255, 128.0.0.0-198.17.255.255, 198.20.0.0-255.255.255.255`；IPv6 补集排除 `::1`；允许/拒绝判定（含 IPv4 映射 IPv6、局域网）。
- Clash Verge 配置解析、日志脱敏（Bearer / UUID）、系统代理端口匹配、域名匹配。
- HTTP 解析（普通 / chunked / 401）。
- 出站链解析：GLOBAL→组→节点、GLOBAL→DIRECT 识别、环形组判为不可信。
- **保护状态机**（用假防火墙记录动作顺序）：
  - 启动即锁定，规则以锁定状态创建；
  - 异常时动作顺序严格为 **锁定 → 结束进程 → 通知**，通知文案与需求一致；
  - 代理恢复后保持锁定、不自动打开 Claude，需手动启动；服务重启后仍记得需手动解锁；
  - 启动前检测失败拒绝启动；Claude 未运行时异常只锁定；
  - 探测抖动第一次只锁不杀、第二次关闭；连接走 DIRECT 第一次即关闭；
  - 网络切换 → 锁定 → 重新验证通过才解锁；
  - 设置锁定失败 → 按「仍锁定 + 防火墙异常」处理，绝不假定已放开；检测器自身异常 → 锁定；
  - 非保护状态下 Claude 启动 → 结束 + 通知；检测中启动 → 不误杀、立即复检；已保护时放行。
- 本地通信鉴权（真实命名管道）：任意进程可读状态；非安装目录的程序调用解锁命令被拒绝。

### 1.3 对真实 Clash Verge / Claude 的只读联调 —— 通过
`ClaudeVPNGuard.Service.exe diag`，原始输出：`evidence-diag.txt`（原始输出未随公开版发布）。验证了：
- 自动发现 Mihomo 命名管道控制接口（配置文件里的管道名与实际不一致，靠枚举找到）并鉴权成功；
- 读取模式（全局）、解析 GLOBAL 出站链到 VLESS 节点及延迟；
- 发现 Claude 桌面版 MSIX 主程序与 Claude Code 程序，并核实 Anthropic 签名；识别运行中 Claude 进程 14 个；
- 连接审计：通过「本地源端口 → TCP 表 → PID」识别出 Claude 经代理的 12 条连接，均非 DIRECT；
- 系统代理指向内核端口校验；
- 真实探测：经 7897 CONNECT api.anthropic.com，TLS 1.3 握手成功，并在内核连接表中确认该连接出站为 `🇯🇵Japan 03`；
- 出口 IP 查询成功（JP）。
- 开发中发现并修复：①Mihomo 需收到 ClientHello 才登记连接；②.NET Framework 默认 TLS 版本过旧导致握手失败；③服务重启后丢失「需手动解锁」状态；④锁定失败时状态被覆盖；⑤网络抖动重验期间新 Claude 子进程会触发误杀。

### 1.4 GUI 冒烟
GUI 可启动、无服务时显示「保护服务停止」并常驻托盘（未做截图级逐项验收）。


## 3. 建议的验收步骤（安装后约 10 分钟）

1. `selftest` 全部通过。
2. Clash Verge 正常 → 保护器「已保护」→ 点「启动 Claude」能正常对话。
3. 在 Clash Verge 里切到「直连」模式 → 2 秒内 Claude 被关闭、弹通知、状态「Claude 已阻断」。切回全局/规则 → 不自动打开；点「启动 Claude」才放行。
4. 退出 Clash Verge → Claude 被关闭；此时从开始菜单直接开 Claude → 被立即结束并提示。
5. 关闭 Wi-Fi 再打开 → 状态短暂「检测中」后恢复「已保护」，Claude 未被误杀。
6. 结束 `ClaudeVPNGuard.exe`（GUI）→ 服务状态不变；`sc stop ClaudeVPNGuard` → `Get-NetFirewallRule -Group ClaudeVPNGuard` 规则仍在且 Lock 规则已启用。
