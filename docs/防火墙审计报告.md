## 2. 审计问题与结论

| 问题 | 结论 | 证据类型 |
|---|---|---|
| 永久规则能否真的限制 Claude 直连 | V1 的 Windows 防火墙静态规则 + V2 的 WFP 阻断过滤器，两层独立 | **待 selftest 实测**（V1 自检阶段 2、WFP 阶段 1） |
| 允许规则与阻断规则谁优先 | Windows 防火墙中阻止优先于允许（IPsec override 除外，本机没有）。MSIX 自带的 2 条允许规则**不会**抵消阻断。WFP 中，本子层的阻断不会被其他子层的普通允许覆盖；只有“硬允许”（清除 action right）才能覆盖，它是否存在由实测结果体现 | 代码 + 审计；需实测 |
| IPv4/IPv6 | 过滤器同时下发到 `ALE_AUTH_CONNECT_V4` 和 `V6`；V1 规则覆盖 IPv6 全段（::1 除外） | 代码；IPv4 待实测；IPv6 本机无全局地址，**未验证** |
| DNS / UDP | `ALE_AUTH_CONNECT` 层同时作用于 UDP，所以 Claude 自己发起的 DNS、QUIC、DoH 都会被拦。系统 DNS 客户端（svchost）代为解析不归属 Claude，属已知限制 | 代码；UDP DNS 待实测 |
| 回环 127.0.0.1 / ::1 | Windows 防火墙规则不管回环。WFP 过滤器在自有最高权重子层显式阻断回环的通用代理端口 | **关键未验证项**：selftest W4/W5 |
| Claude 子进程 | 安装目录下所有 Anthropic 签名的 exe 都单独加过滤器；git/node 等通用程序除外（见限制） | 代码 |
| Claude 更新后路径变化 | WMI 进程启动事件 + 每 2 分钟重扫，新路径立即补加过滤器；在 WFP 事务里重建，失败时整体回滚，原过滤器保持不变 | 代码；实测需等 Claude 真实更新 |
| 重启后规则是否还在 | Windows 防火墙规则是持久的；WFP 过滤器、provider、子层都带 PERSISTENT 标志 | **未验证**：`selftest --keep` → 重启 → `selftest --after-reboot` |
| 服务崩溃后规则是否有效 | 只使用持久过滤器；selftest 阶段 3 由子进程下发后被强制结束，再复测 | 待实测 |
| Mihomo 是否存在不受控的直连路径 | WFP 不约束 Mihomo。Claude 经专用入口的流量由 `listener.proxy` 固定出站（已用真实 Mihomo 实验验证）；Mihomo 自身行为的剩余风险见限制第 4 条 | 真实 Mihomo 实验 + 检测 |
| 是否影响局域网 / spacedesk | 每个过滤器都带 `ALE_APP_ID` 条件，只匹配 Claude 程序；不改系统默认策略，也不加全局过滤器。`audit`（管理员）会逐个列出并统计“无程序条件”的数量，必须为 0。selftest 另外实测：未受保护的进程直连和回环都不受影响 | 代码；静态证明需管理员 audit |

## 3. 安装前检查与事务性

- `install.ps1` 的执行顺序：preflight（有阻止项则不做任何修改）→ `netsh advfirewall export` 导出完整策略 → 导出本程序现有规则清单 → 备份旧版本程序与设置 → 暂存 → 应用 → `verify`（检查服务运行、规则/过滤器完整）。
- 回滚：
  - 升级失败时，恢复旧版本并重新注册，**不删除任何原有规则**。
  - 全新安装失败时，只删除本次新建的项目。
- WFP 规则都在单个 WFP 事务中重建，失败会整体回滚，旧过滤器保持不变。
- 应急恢复：`scripts\recover.ps1`。它会使用 `ProgramData\ClaudeVPNGuard\recovery` 下的副本删除 WFP 过滤器，所以即使安装目录损坏也能清理干净。
